Features

Built for the people who run the room.

Everything below is done in the Bluvu editor, in a web browser, while the wall is live.

01

Map the room, not a grid

Place each screen exactly where it hangs: any position, any gap, any tilt. Portrait panels, screens mounted upside down, odd sizes beside a big centre wall. Bezel gaps go in as pixels or millimetres, so straight lines stay straight across the frames.

  • Wall tool builds a grid with bezel correction in seconds
  • Tilt any screen to the angle it hangs at: drag its handle, hold Shift for 15° steps, or nudge with [ ]
  • Several walls and single displays in one layout
02

An editor you already know how to use

Drag a region to move it, pull a corner to resize it. Frames snap to each other's edges and centres. Every output has a live preview, so you see what each screen is showing without walking to it.

  • Layer list: drag to reorder, bring to front, send to back
  • Inspector for exact crop, scale and rotation
  • The last 50 versions of every layout, one click to restore
03

Any source, layered

Mix NDI streams, capture cards, video files, images and solid colour on one canvas. Stack them with opacity and crop, save the look as a scene, and crossfade between scenes.

  • MP4 and MOV (H.264, HEVC, AV1) up to 8K, with loop, pause and restart
  • A fallback image per wall when a signal drops
  • Name tags on layers, to tell inputs apart on the glass
  • Colour correction per output
04

Screens that set themselves up

Install Bluvu on a receiving PC and point it at the media server. It shows up in the editor with its screens listed. Click Set up, pick what each screen shows, and within seconds it's playing full screen.

  • Online and playing status for every PC and every screen
  • The player installs and updates itself on each PC
  • Swap a dead PC for one with the same name and it picks up the same setup
  • Keeps showing the last picture if the media server goes away
05

In step, and it shows you

Every screen's picture is rendered from the same frame, in one GPU pass. The Bluvu player shows those frames in step across a PC's screens, and lines up several PCs with a shared buffer. The editor reports how far apart the screens really are, instead of leaving you to guess.

  • One stream split across a 2×2 on one PC, always the same frame
  • A delay for screens cabled straight to the server, to match the network walls
  • Built-in frame-counter test pattern to check sync with a phone camera
06

Sound that follows the picture

Send the audio of any stream or sound input to the media server's sound devices: bar speakers, the patio, the back room. Each zone gets its own source, volume and mute, delayed to match the screens.

  • Per-zone source, volume, mute
  • Mono on one output of a device
  • Controlled by the same API as the video
07

Built to run unattended

Bluvu is made for screens nobody is watching the back of. It starts hidden at boot, waits for the network, and restarts anything that stops. If a graphics driver resets, only that wall pauses, and it comes back on its own.

  • Each screen remembers its monitor, even when Windows renumbers them
  • Update everything updates every PC from the editor
  • Optional PIN for the editor and key for the API
  • Switch one screen off (black) while its PC stays on

How it works

One canvas in. Every screen out.

Sources land on a virtual canvas on the media server. Bluvu cuts each screen's piece out of that canvas and sends it on: over the network to a receiving PC, or straight out of the server's own graphics card.

  1. Install on the media server and on each receiving PC. One double-click each.
  2. Draw your walls in the editor, or build a grid with the wall tool.
  3. Assign each receiving PC's screens as they check in.
  4. Save presets and hand staff a Stream Deck, a tablet or your control system.

Control

Staff press a button. The wall changes.

Save a preset per wall (the big game full screen, four games in quarters, the menu board) and recall it from anything that can send a web request. No login dance, no drivers, no plug-in to buy.

  • Presets, scenes, playlists and arrangements per wall
  • "Show this stream on that wall" in a single request
  • Sound zones: source, volume, mute
  • Live status and stream thumbnails for touch panels
# Big game, full wall, half-second fade
curl -X POST http://media-server:8090/api/walls/main-wall/presets/game-full/recall \
  -H "Content-Type: application/json" \
  -d '{"transitionMs": 500}'
# Put the slides PC on the double-wide
curl -X POST http://media-server:8090/api/walls/double-wide/show \
  -H "Content-Type: application/json" \
  -d '{"ndiName": "GFX-PC (Slides)", "transitionMs": 500}'
# Every wall, its presets, and what's on now
curl http://media-server:8090/api/control

Plain HTTP and JSON. Bitfocus Companion, Crestron, Q-SYS and AMX can all send these.

FAQ

Questions we get.

What hardware do I need?

One Windows PC with a GPU as the media server. Screens connect either directly to that PC's graphics outputs, or to small receiving PCs on the same network. Bluvu doesn't need a dedicated video-wall processor.

Do I need NDI?

For screens on receiving PCs, yes: Bluvu sends each screen's picture as an NDI stream. Screens cabled straight to the media server don't use the network at all. Sources can be NDI, capture cards, video files or images.

Will the screens be in sync?

Every screen is rendered from the same frame. Screens on one PC running the Bluvu player are shown in step, and several PCs can be lined up with a shared buffer to within one refresh of each other. The editor shows the measured spread, so you can see it for yourself.

Can my control system drive it?

Yes. Everything staff need (presets, streams per wall, sound zones) is a plain HTTP request with JSON. Bitfocus Companion, Crestron, Q-SYS, AMX or a script can all send them.

What happens when a PC reboots or a cable is pulled?

Bluvu starts at logon, waits for the network, and restarts anything that stops. Each screen remembers which monitor it belongs to and waits for it to come back. A receiving PC keeps its last setup even if the media server is unreachable.
